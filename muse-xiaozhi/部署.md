# Muse 版小智：部署说明（给家里 Ubuntu 上的 Muse 照着做）

## 0. 先读

**目标**：在家里的 Ubuntu（主机 homelink-5c7679，yc 账户）上装好"小智服务端"，让桌上的小智板子能和 Muse 对话：

```
板子（按键或说"小明同学"）--局域网--> Ubuntu：小智服务端（语音转文字）
   --musegadget send-user-msg--> Muse 副聊天（手机 App 里能看到完整回答）
   --Muse 调 file.write 把"念的版本"写进收件箱--> 小智服务端（文字转语音）--> 板子念出来
```

**规则**
- 按顺序做。每一步先贴命令的原始输出，再用大白话总结。
- 同一个步骤失败两次就停下，不要换别的办法继续试。告诉我：卡在哪一步、原始报错、你认为的原因。等我回复再继续。
- 标【人】的步骤到了就停下叫我。
- **红线**：
  - 只**调用** musegadget，不改它的服务、配置、安装目录；
  - 不碰 guest 账户、guest 桌面、NinjaDesktop 和翻墙设置；
  - 不在任何文件、脚本、日志、回复里写密码或口令（说"已填好"即可）；
  - 所有东西放在 yc 账户下。
- 版本按 `VERSIONS.md` 写死，不要升级、不要换软件。

**约定**
- 仓库放在 `/home/yc/xianliao-ba`，本项目在 `/home/yc/xianliao-ba/muse-xiaozhi`，下面简称"项目目录"。
- 服务端端口 **8800**。
- Ubuntu 的局域网 IP 记作 `<IP>`（第 1 步查到）。

## 1. 查 IP 和基本情况

```bash
hostname -I
python3 --version
ss -ltnp | grep -E ':8800\b' || echo "8800 空闲"
command -v musegadget
sudo ufw status
```
- `<IP>` 取局域网那个地址（一般 192.168. 开头）。建议在路由器里给这台电脑做"固定 IP（DHCP 保留）"，否则 IP 变了板子会连不上。
- Python 应是 3.12.x（Ubuntu 24.04 自带）。8800 被占用就停下问人。

## 3. 装服务端

```bash
sudo apt-get install -y python3-venv libopus0
cd /home/yc/xianliao-ba/muse-xiaozhi/server
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python tools/download_models.py
```
- `libopus0` 是语音压缩库（Linux 上用系统自带的，不需要 Windows 那个 opus.dll）。
- 模型约 300MB，下载慢就耐心等。校验值对不上只会提醒、照样使用。最后一行应是"模型都准备好了"。

## 4. 配置

```bash
cd /home/yc/xianliao-ba/muse-xiaozhi/server
cp config.example.yaml config.yaml
python3 -c "import secrets; print(secrets.token_hex(16))"
python3 -c "import uuid; print(uuid.uuid4())"
mkdir -p /home/yc/muse-xiaozhi/inbox
```
编辑 `config.yaml`：
- `server.api_token` 改成第一条打印的随机串；
- `muse.session_id` 改成第二条打印的 UUID（小智的问答都进这个副聊天，不进主聊天；必须是 UUID 格式，否则云端报 `400 invalid session_id`）；
- 其他不用改。`muse.inbox_dir` 默认 `~/muse-xiaozhi/inbox`，就是刚建的文件夹。

## 5. 测 Muse 来回一圈（不接板子）

```bash
cd /home/yc/xianliao-ba/muse-xiaozhi/server
.venv/bin/python tools/ask_muse.py "测试：请只回答两个字：收到"
```
- 这条消息会进第 4 步的副聊天。消息里附了说明，请 Muse **照说明做**：回答完以后调用本设备的 `file.write`，把"念的版本"写进说明里给的路径（`/home/yc/muse-xiaozhi/inbox/<编号>.txt`）。
- 应打印 `Muse 写回（X 秒）：收到`。打印"Muse 没有回话"说明没写回来，停下问人。
- 【人】打开手机 Muse App，确认副聊天里有这条问答。

## 6. 试运行

```bash
cd /home/yc/xianliao-ba/muse-xiaozhi/server
.venv/bin/python main.py
```
等十几秒（加载模型），另开一个终端：
```bash
curl -s http://127.0.0.1:8800/
cd /home/yc/xianliao-ba/muse-xiaozhi/server
.venv/bin/python tools/fake_device.py ws://127.0.0.1:8800 ask "今天星期几"
```
- 第一条应返回 `xiaozhi server ok`。
- 第二条：假设备用本机朗读把问题念成语音发过去，最后一行 JSON 里 `heard` 有 Muse 的回答就对了。Muse 回得慢（超过 6 秒）时，`heard` 是"收到，我先去办……"，`notifies` 里是后来主动念的回答，也算对。
- 确认后回第一个终端按 Ctrl+C 停掉。

## 7. 开机自启

```bash
sudo cp /home/yc/xianliao-ba/muse-xiaozhi/deploy/linux/muse-xiaozhi.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now muse-xiaozhi
sleep 20; systemctl --no-pager status muse-xiaozhi | head -5
curl -s http://127.0.0.1:8800/
```
- 第 1 步 `ufw status` 是 active 的话，再执行 `sudo ufw allow from 192.168.0.0/16 to any port 8800 proto tcp`（只放行局域网）。
- 【人】手机连家里同一个 Wi-Fi，浏览器打开 `http://<IP>:8800/`，能看到 `xiaozhi server ok`。打不开 = 板子也连不上，先查防火墙。

## 8. 板子【人】

### 8.1 烧固件
固件在 `muse-xiaozhi/release/`（文件名带 `wn9_xiaomingtongxue_tts2`，从 0x0 整包烧）。由家里 Windows 上的 AI 用 esptool 5.4.0 烧：先整片擦除，再写入 0x0。USB 厂商编号 303A。

### 8.2 配网
1. 板子开机后屏幕提示连热点（`Xiaozhi-XXXX`）。手机连上，浏览器打开 `http://192.168.4.1`。
2. 选家里的 **2.4G** Wi-Fi，填密码。
3. OTA 地址填 `http://<IP>:8800/xiaozhi/ota/`（末尾斜杠别漏）。
4. 保存。重启后屏幕出现 Muse 的小怪兽（待机）。

以后要换 Wi-Fi 或 IP 变了：**连按三下主按键**，回到配网模式。

### 8.3 只认这块板子（建议）
```bash
curl -s -H "Authorization: Bearer <api_token>" http://127.0.0.1:8800/api/status
```
把 `device_id` 填进 `config.yaml` 的 `allowed_devices`，然后 `sudo systemctl restart muse-xiaozhi`。

## 9. 日常用法

| 操作 | 作用 |
| --- | --- |
| 说"小明同学" | 叮一声后开始听 |
| 主按键按一下 | 开始说话（和唤醒词效果一样） |
| 说话时再按一下 | 说完了（不按也行，停顿约 0.8 秒自动结束） |
| 它在说话时按一下 | 打断 |
| 双击主按键 | 开关屏幕背光 |
| 连按三下主按键 | 重新配网 |
| 音量 +/- 键 | 调音量 |

Muse 6 秒内没写回来，小智先说"收到，我先去办，办好了叫你"，小人切到"干活中"；写回来后小智主动开口念。

测试主动开口（不经过 Muse）：`.venv/bin/python tools/say.py "测试一下主动开口"`。

## 10. 出问题先看

| 现象 | 先查 |
| --- | --- |
| 屏幕提示连不上服务器 | `systemctl status muse-xiaozhi`；手机打开 `http://<IP>:8800/`；Ubuntu 的 IP 变没变 |
| 小智说"Muse 那边没连上" | `musegadget` 命令还在不在、服务是否 active；日志里 `连不上 Muse：` 后面的原话 |
| 小智说"刚才那句没问成，原因是 Muse 没有回话" | Muse 回答了但没调 file.write：看手机副聊天里 Muse 有没有回；再跑一次第 5 步 |
| 主动开口没声音 | 日志里 `did not fetch notify audio`：板子没来下载语音，查 8800 端口是否对局域网开放 |
| 识别不准 | 看日志里识别出的原话；常错的词告诉 Claude 加进纠错表 |

日志：`journalctl -u muse-xiaozhi -n 100`，以及 `server/logs/server.log`（自动轮换）。
