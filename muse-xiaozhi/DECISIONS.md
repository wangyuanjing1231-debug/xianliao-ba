# 做过的选择和理由

1. **大脑换成 Muse（2026-10-11）。** 额度足、有记忆，问答记录进手机 App。前身接的是 OpenClaw + DeepSeek。
2. **去程用 `musegadget send-user-msg`，回程让 Muse 调 `file.write`。** Muse 查过 musegadget 源码：发消息的返回值、长连接推送、本机接口都拿不到回复正文；Muse 能对这台设备下发的命令只有 system.run、file.read、file.write、device.health。所以每条消息都附一段说明，请 Muse 回答后把"念的版本"写进 `~/muse-xiaozhi/inbox/<编号>.txt`，服务端看到文件就念。实测来回 5.4 秒。
3. **回程用 file.write 不用 system.run。** 回复文字不经过 shell，不怕引号、`$`、反引号被当成命令。
4. **进副聊天不进主聊天。** `muse.session_id` 填一个 UUID（不是 UUID 云端会报 400），语音问答不冲乱平时的对话。
5. **念的版本单独要。** 手机 App 里看完整回答；板子只念口语、先说重点、一到三句、一百字以内。
6. **慢的先回"收到"。** Muse 12 秒内没写回来，先说"收到，我问问 Muse，回话了叫你"，写回来后主动开口。主动开口用固件自带的"通知"消息（设备自己下载一段语音播放）。
7. **通知音频地址补端口号。** 板子连 WebSocket 时 Host 头里可能不带端口（2026-10-11 在 Windows 上实测），不补的话板子去 80 端口下载、永远拿不到。现在和 OTA 下发地址用同一套规则补上。
8. **唤醒词用"小明同学"（乐鑫 WakeNet9 预设模型 `wn9_xiaomingtongxue_tts2`）。** 预设模型比自定义拼音唤醒词准、误触发少。核对过：锁定的 esp-sr 2.4.7 里有这个模型。唤醒后不把唤醒词录音发给服务端（`CONFIG_SEND_WAKE_WORD_DATA=n`），和按键一样直接开始听。按键说话保留。
9. **一问一答：** 回答完回到待机，不自动继续听。
10. **本机语音：** 识别 SenseVoice（int8，CPU 就能跑，中文准），断句 Silero VAD（停顿 0.8 秒算说完），朗读 Matcha 标贝女声。放射科词先不做热词：Muse 知道你的身份，能从上下文纠正；常错的词再加纠错表。
11. **固件补丁：待机时保持连接。** 服务端才能主动开口；断了悄悄重连（2 秒到 60 秒逐步拉长），服务端每 25 秒打个招呼。
12. **像素小人：** 用你"全家"文件里的爸爸。聆听从"惊讶脸"改成"微笑"（2026-10-11 你说惊讶脸不好看）。Muse 给的小怪兽形象拿到素材后作为正式形象替换。
13. **服务端搬到家里 Ubuntu。** 和 musegadget 在同一台机器上；只调用 musegadget，不改它。
14. **固件编译放在 GitHub 上自动跑。** 开发沙盒连不上乐鑫的组件库；组件版本锁在 `firmware/dependencies.lock`。
15. **模型校验值对不上只提醒、不拦。** 上游会重新上传同名模型文件，硬拦只会卡住部署。
