# 做过的选择和理由

1. **服务端底座：以 frogchou/xiaozhi-openclaw 的思路为底，代码重写。** 它的结构最贴近需求（Python 精简服务端 + OpenClaw），但原版识别和朗读走 OpenAI 云端、还要装 ffmpeg，不符合"本机跑、不花钱"。没用 xinnan-tech（全家桶要 Java 管理后台 + MySQL + Redis，8G 内存吃力、要锁的版本太多），也没用 hackers365（Go 写的，功能全但重）。协议细节对照了 xinnan-tech 和固件源码。
2. **接 OpenClaw 用它自带的问答接口（OpenAI 兼容的 `/v1/chat/completions`），不写聊天渠道插件。** 官方接口最稳，锁版本后最不容易坏；每台设备固定一个会话，能接着上文聊。
3. **本机语音：** 识别用 SenseVoice（int8 量化版，CPU 就能跑，中文准）；判断说完没有用 Silero VAD（停顿 0.8 秒算说完）；朗读用 Matcha 标贝女声（和 Kokoro、MeloTTS 比过，中文清楚、速度快）。
4. **不念符号：** 服务端把 Markdown、链接、表情、代码块都去掉；百分号、单位、"2~3"、英文缩写转成读法；同时让 OpenClaw 用口语、一到三句话回答。
5. **长任务：** OpenClaw 6 秒还没开口，先说"收到……办好了叫你"，转后台；念到一半卡住 10 秒也转后台；办完后服务端主动让小智开口。主动开口用固件自带的"通知"消息（设备自己下载一段语音播放）。
6. **固件补丁：待机时保持连接。** 原版说完话就断开，服务端没法主动开口；补丁让它待机也连着、断了悄悄重连（2 秒到 60 秒逐步拉长），服务端每 25 秒打个招呼。
7. **一问一答：** 回答完回到待机，不自动继续听（科室里人多声杂，免得误触发）。按一下开始说，再按一下或停顿就结束；它说话时按一下就打断。
8. **关掉唤醒词和回声消除：** 只用按键。代价是不能张嘴插话打断，要按键。
9. **屏幕：** 只放像素小人和系统提示，对话文字不上屏（1.54 寸太小，看不清反而乱）。
10. **像素小人：** 用你"全家"文件里的爸爸（啤酒肚），拿原来的绘制代码生成 7 套动作：待机、聆听、思考、说话、干活中、干完了，外加出错。
11. **大模型：** DeepSeek `deepseek-flash`，关深度思考。Kimi K3 在 OpenClaw 里每次都强制最长思考，语音等太久，所以这条线不用它。
12. **安全：** OpenClaw 只允许本机访问；关掉执行命令（对着它说话的人谁都可以）；关掉自动更新和聊天里触发的重启；"让小智开口"接口要口令；可以只认自己这台设备。
13. **固件编译放在 GitHub 上自动跑。** 开发沙盒连不上乐鑫的组件库，本地编不了。第一次编译出的组件版本表（`dependencies.lock`）存进仓库，以后编出来的都一样。
14. **存放位置：** 新建私有仓库被权限拒绝（试了两次），按你的要求放进 xianliao-ba 仓库的 `keshi-xiaozhi` 文件夹，原有内容没动。
15. **聊天软件接入：按你的要求暂停。** 插件里"让小智念一句话"的接口留着，以后要接再说。
