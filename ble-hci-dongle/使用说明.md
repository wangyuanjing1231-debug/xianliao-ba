# Pocket-Dongle-S3 临时当蓝牙接收器（Ubuntu 24.04）

固件文件：`ble-hci-dongle/release/ble-hci-dongle_esp32s3_flash-at-0x0.bin`（从 0x0 地址整片烧录）
原来的固件：`release/esp32-bridge-flash-at-0x0.bin`（同样从 0x0 烧录）

工作原理一句话：板子里的蓝牙芯片只当"无线电"（蓝牙控制器），配对、加密这些"大脑"工作仍由 Ubuntu 自带的蓝牙服务 BlueZ 来做；两者之间通过 USB 串口传话，传话格式叫 H4（蓝牙标准里规定的串口传话格式）。所以电脑上需要一个叫 `btattach` 的小程序，把这个串口"接"给 BlueZ。

下面所有命令都在"终端"里输入（Ubuntu 里按 Ctrl+Alt+T 打开）。

---

## 第 0 步：装烧录工具（只做一次）

```
sudo apt install -y python3-venv
python3 -m venv ~/esptool-env
~/esptool-env/bin/pip install esptool
sudo usermod -aG dialout $USER
```
（大白话：建一个独立的小 Python 环境，在里面装乐鑫官方的烧录工具 esptool；最后一行让你这个账号有权限用串口，**做完要注销再登录一次**才生效。）

## 第 1 步：让板子进"烧录模式"

按住板子上的 BOOT 键不放，把板子插进电脑，插好后松手。然后：

```
ls /dev/ttyACM*
```
（大白话：看看电脑上多出来的串口叫什么。正常会出现 `/dev/ttyACM0`。下文都按 `/dev/ttyACM0` 写，如果你看到的是 ttyACM1 之类，就把命令里的名字换掉。）

## 第 2 步：先把板子里现在的固件整个备份下来（强烈建议）

```
~/esptool-env/bin/esptool --chip esp32s3 -p /dev/ttyACM0 read-flash 0 0x1000000 ~/pocket-dongle-backup.bin
```
（大白话：把板子 16MB 存储芯片从头到尾原样读出来，存成家目录里的 `pocket-dongle-backup.bin`，大约要几分钟。仓库里虽然有原固件，但板子上可能还存着 Wi-Fi 设置等数据，整片备份最保险。）

## 第 3 步：刷入蓝牙接收器固件

先从仓库下载 `ble-hci-dongle/release/ble-hci-dongle_esp32s3_flash-at-0x0.bin` 到家目录，然后：

```
~/esptool-env/bin/esptool --chip esp32s3 -p /dev/ttyACM0 write-flash 0x0 ~/ble-hci-dongle_esp32s3_flash-at-0x0.bin
```
（大白话：把新固件从地址 0x0 开始写进板子。）

写完后**拔下板子，再插上（这次不按 BOOT）**。

## 第 4 步：让系统认它

### 4.1 先看电脑原来的接收器是谁

```
ls /sys/class/bluetooth/
readlink /sys/class/bluetooth/hci0/device/driver
```
（大白话：第一行列出系统现在认得的蓝牙接收器，一般只有 `hci0`，就是原来那个。第二行看它用的是哪个驱动；结尾是 `btusb` 说明它是走 USB 的，绝大多数笔记本内置的都是这种。）

### 4.2 把原来的接收器"拔掉"（软件上）

如果上一步看到的驱动是 `btusb`：

```
sudo modprobe -r btusb
```
（大白话：把原接收器的驱动卸掉，它就从系统里消失了。这样新板子接上后会占用 `hci0` 这个名字，很多软件默认就用 `hci0`，最省心。我们的板子不走 btusb，不受影响。）

如果驱动不是 `btusb`，改用：

```
rfkill list bluetooth
sudo rfkill block <上面列出的原接收器编号>
```
（大白话：rfkill 是系统的"无线开关"，把原接收器关掉。这时它还占着 hci0，新板子会叫 hci1，见 4.5。）

### 4.3 关掉会乱碰串口的服务

```
sudo systemctl stop ModemManager
```
（大白话：Ubuntu 有个"上网卡管理"服务，看见新串口会往里发试探命令，会把蓝牙传话搅乱。只是暂停，重启电脑会自动恢复。）

### 4.4 清掉开机杂讯，然后接入

```
sudo stty -F /dev/ttyACM0 raw -echo
timeout 1 cat /dev/ttyACM0 > /dev/null
sudo btattach -B /dev/ttyACM0 -P h4 -N
```
（大白话：
- 第一行：把串口设成"原样传输、不回显"。
- 第二行：读 1 秒并扔掉。板子开机时芯片自带的启动程序会往 USB 口吐几行字，这些不是蓝牙数据，先清掉。
- 第三行：把这个串口接给 BlueZ。`-P h4` 是传话格式，`-N` 是不用硬件流控（USB 串口不需要）。

**第三行运行后不会自己结束，这个终端窗口要一直开着**；关掉它或按 Ctrl+C，板子就从系统里断开。）

### 4.5 确认系统认到了

另开一个终端：

```
bluetoothctl list
btmgmt info
```
（大白话：第一行列出 BlueZ 认得的接收器；第二行显示每个接收器的详细信息。能看到一个新的接收器，名字前面是 `hci0`（如果 4.2 用了 btusb 卸载）或 `hci1`（如果用了 rfkill），`current settings` 里有 `powered` 和 `le` 就说明好了。记下它的地址（形如 `XX:XX:XX:XX:XX:XX`）。）

如果没有 `powered`：

```
bluetoothctl power on
```

如果新板子是 `hci1`，在 `bluetoothctl` 里先选中它：

```
bluetoothctl
select <新板子的地址>
show
```
（大白话：告诉蓝牙服务"默认用这个接收器"，`show` 里的地址应该是新板子的。输入 `quit` 退出。）

## 第 5 步：确认 Muse 服务用的是它

注意：我不知道 Muse 服务内部是怎么用蓝牙的，下面是通用的确认方法。

**最省事的保证**：用 4.2 的 `modprobe -r btusb` 把原接收器卸掉。这样系统里只剩新板子一个接收器，任何程序都只能用它。

**亲眼确认**：配对前另开一个终端运行：

```
sudo btmon -i hci0
```
（大白话：btmon 是蓝牙"监听器"，会实时打印这个接收器上来往的每一条消息。`hci0` 换成新板子的名字。）

然后让手机去连电脑 / 让 Muse 开始配对。如果 btmon 窗口里刷出 `LE Connection Complete`、`Pairing`、`Encryption Change` 之类的行，说明这次配对确实走的是新板子。如果 btmon 一直安静、但配对仍在进行，说明走的是别的接收器。

配对成功后也可以查：

```
btmgmt --index 0 con
```
（大白话：列出这个接收器上当前连着的设备，应该能看到手机的地址。`--index 0` 对应 hci0，hci1 就写 1。）

## 第 6 步：用完恢复电脑原状

1. 在运行 `btattach` 的终端按 Ctrl+C，拔下板子。
2. 把原接收器装回来：
   ```
   sudo modprobe btusb
   ```
   （如果当初用的是 rfkill：`sudo rfkill unblock <编号>`）
3. `sudo systemctl start ModemManager`（或直接重启电脑）。

注意：配对信息存在电脑的 BlueZ 里，**是跟接收器的地址绑定的**。换回原接收器后，这次配对的记录不会自动跟过去。

## 第 7 步：以后刷回原来的固件

新固件下，板子插上直接就是 `/dev/ttyACM0`，一般不用按 BOOT 键（如果下面命令报连不上，就按第 1 步的办法按住 BOOT 插上）。先确认 `btattach` 已经停掉。

二选一：

**用仓库里的原固件**（板子上 Wi-Fi 设置等会回到默认）：

```
~/esptool-env/bin/esptool --chip esp32s3 -p /dev/ttyACM0 write-flash 0x0 ~/esp32-bridge-flash-at-0x0.bin
```

**用第 2 步的整片备份**（和刷之前一模一样）：

```
~/esptool-env/bin/esptool --chip esp32s3 -p /dev/ttyACM0 write-flash 0x0 ~/pocket-dongle-backup.bin
```

写完拔插一次。原固件是"USB 键盘 + 串口"模式，拔插后会重新被电脑认成键盘。

## 常见问题

- **btattach 报 `Failed to set protocol` 或 BlueZ 一直看不到新接收器**：拔插板子，重新从 4.4 第一行做起（开机杂讯没清干净时会这样）。
- **esptool 报 `Permission denied`**：第 0 步的 dialout 权限还没生效，注销重登；或者命令前加 `sudo`。
- **这块板子只支持低功耗蓝牙**：ESP32-S3 的蓝牙硬件本身就不支持经典蓝牙（耳机、音箱那种），所以它只能做低功耗蓝牙配对。
