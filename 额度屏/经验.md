# 额度屏经验记录

## 踩过的坑与原因

1. **Antigravity 配额 API 分组差异**
   - 现象：`retrieveUserQuotaSummary` 接口在部分订阅账号（如 Google AI Pro）下仅返回 `Claude and GPT models` 组，不包含 Gemini 组。
   - 原因：Gemini 在高阶订阅中属于专用配额池，直接调用 `/v1internal:retrieveUserQuota` 才能拿到包括 `gemini-2.5-flash` 在内的全部真实百分比和精确到秒的 `resetTime`。

2. **喇叭鸣叫后麦克风回响自停**
   - 现象：板子鸣叫后未拍手就瞬间自停。
   - 原因：微雪这块板子喇叭与麦克风（ES7210）同板仅隔 2 厘米，蜂鸣发出后喇叭余振和 I2S DMA 缓冲里残留高幅值音频，被麦克风当成拍手。
   - 解决：鸣叫完毕后立即拉低功放使能脚（`digitalWrite(PA_CTRL, LOW)`），并延时 250ms 彻底清空 I2S DMA 接收缓冲，然后才启动拍手监听；拍手阈值设为 12000（背景噪音仅 40 左右），完美隔离底噪与余振。

3. **透明代理 DNS 解析异常**
   - 现象：宿主机访问 `daily-cloudcode-pa.googleapis.com` 报 `SSL_ERROR_SYSCALL`。
   - 原因：本地透明代理将该域名解析至保留 IP（198.18.0.x）但节点握手中断。
   - 解决：在 Python 监控服务中对 `daily-cloudcode-pa.googleapis.com` 做 IP 预置（172.217.119.4），直连握手秒通。

4. **主网与前置 Wi-Fi 子网路由**
   - 现象：需要确认前置子网 `192.168.7.x` 能否访问宿主机 `192.168.6.170`。
   - 验证：主路由防火墙已配置 `qianzhi` 与 `lan` 之间的双向 ACCEPT 转发，实测板子直接 `http://192.168.6.170:8888/api/quota` 毫秒级通信，无需修改路由器。

5. **任务 024：微雪板子按键硬件映射**
   - 现象：板子有三个实体按键，需要明确左右音量键和主按键的 GPIO。
   - 解决：通过硬件引脚核对，BOOT 键为 GPIO 0（右侧音量键），PLUS 键为 GPIO 4（左侧音量键），主按键/电源键为 GPIO 5。将 GPIO 4 和 GPIO 0 设为双向翻页，GPIO 5 设为主关报警键，并在报警状态下支持任意按键一触关停。

6. **Gemini 网页版额度抓取机制**
   - 现象：Gemini 网页版与 Antigravity 为独立配额池，且 Google 页面采用 TrustedHTML 限制 innerHTML 注入。
   - 解决：通过宿主机常驻的 Playwright MCP 浏览器服务，以 `browser-cli open https://gemini.google.com/usage` 配合 `browser_evaluate` 的 DOM 正则解析，定时（30分钟）抓取 5 小时用量与每周用量。通过实测网页发测试消息，观察到用量数字由 25% 变为 29%，完全确认抓取到的数据为真实动态额度。
